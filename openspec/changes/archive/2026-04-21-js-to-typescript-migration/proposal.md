## Why

The codebase is a mix of JavaScript (27 files) and TypeScript (54 files). The remaining JS/JSX files lack type safety, rely on `prop-types` for runtime checks instead of compile-time guarantees, and require maintaining a dual build pipeline (babel-jest for JS, ts-jest for TS). Completing the migration eliminates this split, enables `strict` mode across the entire codebase, and simplifies the build and test toolchain.

## What Changes

-   Convert 19 `.js` files to `.ts` and 7 `.jsx` files to `.tsx` under `src/`. (`src/locales/index.js` is excluded — it is auto-generated by `d2-i18n-generate` and overwritten on every build.)
-   Replace `prop-types` runtime validation with TypeScript interfaces/types.
-   Add type annotations to function signatures, props, state, and module exports.
-   Remove `allowJs: true` from `tsconfig.json` after all files are converted.
-   Simplify `jest.config.js` to use `ts-jest` exclusively (drop `babel-jest` JS transform).
-   Remove `prop-types` from `devDependencies` if no longer referenced.
-   Clean up root config files (`setupEnzyme.js` -> `.ts`, `.eslintrc.js` -> `.eslintrc.js` stays as config).

_None. This is a refactor with no new behavioral capabilities._

### Modified Capabilities

_None. No spec-level behavior changes — all components retain their existing public APIs._

## Impact

-   **Source files**: 26 files renamed and rewritten with type annotations across 8 component directories plus `utils/` and `helpers/`.
-   **Build pipeline**: `tsconfig.json` tightened (remove `allowJs`). `jest.config.js` simplified.
-   **Dependencies**: `prop-types` removed from all source imports and can be dropped from `devDependencies`. No runtime dependency changes.
-   **Public API**: Zero changes — all exported types and component interfaces remain identical.
-   **DHIS2 `d2` library**: Some interop points may require `any` casts or thin type declarations where the `d2` library lacks types.
